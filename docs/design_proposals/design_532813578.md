# Technical Design & Implementation Plan: ClickHouse XMC Client Library



## 1. Executive Summary & Reviewer Question Responses



This updated technical design proposal addresses **Buganizer Task 532813578 ([XMC Flatboard] Clickhouse XMC client)**. The primary objective is to implement a robust, modular client library within [pkg/clickhouse](file:///tmp/koder_workspaces/task_532813578/xmc/pkg/clickhouse) responsible for ClickHouse database connectivity, resilient multi-strategy authentication fallback, SQL translation from XMC proto queries, and mapping query result sets to [ChartData](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/dashboard/messages.proto#L215-L265) proto messages.

### Detailed Answers to Reviewer Questions & Code Alignment Audit

1. **Metrics Table Schema & Column Naming Alignment**:
   - **Question**: *Is standard schema (`xid`, `wid`, `metric_name`, `metric_value`, `iteration`, `timestamp`) with configurable table name (`CLICKHOUSE_METRICS_TABLE`) acceptable?*
   - **Resolution**: **Yes, fully acceptable**. Cross-referencing [api/protos/metrics/metrics.proto](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/metrics/metrics.proto#L23-L32) lines 23\u201332 confirms the core metric fields stored in XMC: `xid`, `work_unit_id`, `execution_id`, `replica_id`, `metric_name`, `metric_value`, `step`, and `timestamp` (in microseconds).
   - **Aliasing Strategy**: To bridge field naming differences between [api/protos/metrics/metrics.proto](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/metrics/metrics.proto#L24-L31) (`work_unit_id`, `step`) and [api/protos/dashboard/messages.proto](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/dashboard/messages.proto#L57-L58) (`wid`, `iteration`), the translation engine in [pkg/clickhouse/translator.go](file:///tmp/koder_workspaces/task_532813578/xmc/pkg/clickhouse/translator.go) explicitly aliases ClickHouse table columns (`SELECT work_unit_id AS wid, step AS iteration...`) in generated queries.
   - **Timestamp Microsecond Conversion**: [metrics.proto](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/metrics/metrics.proto#L31) line 31 specifies `int64 timestamp = 8; // Timestamp in microseconds`. Result set mapping in [pkg/clickhouse/mapper.go](file:///tmp/koder_workspaces/task_532813578/xmc/pkg/clickhouse/mapper.go) converts microsecond timestamps to `google.protobuf.Timestamp` using `time.UnixMicro(t)` and `timestamppb.New`.

2. **Downsampling Algorithm Prioritization**:
   - **Question**: *Should ClickHouse LTTB (Largest Triangle Three Buckets) or integer step aggregation (`floor(iteration / step)`) be prioritized for initial implementation?*
   - **Resolution**: **Prioritize deterministic integer step / time-window bucket aggregation**. Window-based aggregation using `floor(step / step_size)` (or time-interval bucketing) runs deterministically across standard ClickHouse database engines without requiring external UDF extensions or specific engine versions. The SQL builder in [pkg/clickhouse/translator.go](file:///tmp/koder_workspaces/task_532813578/xmc/pkg/clickhouse/translator.go) is modularly structured to allow LTTB downsampling to be added seamlessly as an optional extension in future iterations.

3. **Code Comment & Constraint Verification**:
   - Code comments in [api/protos/metrics/metrics.proto](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/metrics/metrics.proto#L31), [api/protos/dashboard/messages.proto](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/dashboard/messages.proto#L25-L63), [pkg/clickhouse/clickhouse.go](file:///tmp/koder_workspaces/task_532813578/xmc/pkg/clickhouse/clickhouse.go#L30-L83), and [pkg/apis/metrics/types.go](file:///tmp/koder_workspaces/task_532813578/xmc/pkg/apis/metrics/types.go#L25-L62) were audited. ## 3. Detailed Technical Specification

### 3.1 Resilient Multi-Strategy Authentication Fallback (`auth.go`)
Per the scope requirements, `ConnectWithFallback` executes a sequential multi-strategy authentication sequence before returning an error:

1. **Strategy 1 (Primary Configured Credentials)**:
   - Reads `CLICKHOUSE_DSN` or (`CLICKHOUSE_USER` and `CLICKHOUSE_PASSWORD`).
   - Attempts connection via `clickhouse.Open(opts)` and verifies with `conn.Ping(ctx)`.
2. **Strategy 2 (Configured User with Empty Password)**:
   - Uses configured `CLICKHOUSE_USER` (or `\"default\"`) with empty password `\"\"`.
   - Attempts connection and ping verification.
3. **Strategy 3 (Anonymous / Default Access)**:
   - Uses username `\"default\"` and password `\"\"`.
   - Attempts connection and ping verification.

If all strategies fail, an aggregated error combining failure details from each step is returned.

```go
// ConnectWithFallback attempts multi-strategy authentication sequence before returning an error.
func ConnectWithFallback(ctx context.Context) (driver.Conn, error) {
    var errs []error
    strategies := []func() (*clickhouse.Options, error){
        GetOptions,
        getOptionsUserNoPassword,
        getOptionsDefaultUser,
    }
    for _, getOpts := range strategies {
        opts, err := getOpts()
        if err != nil {
            errs = append(errs, err)
            continue
        }
        conn, err := clickhouse.Open(opts)
        if err != nil {
            errs = append(errs, err)
            continue
        }
        if err := conn.Ping(ctx); err == nil {
            return conn, nil
        }
        conn.Close()
    }
    return nil, fmt.Errorf(\"all clickhouse auth strategies failed: %v\", errs)
}
```

### 3.2 SQL Query Translation Engine (`translator.go`)
Translates XMC proto definitions from [api/protos/dashboard/messages.proto](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/dashboard/messages.proto) into parameterized ClickHouse SQL statements.

#### Schema & Aliasing Assumptions:
- Table name defaults to `xmc_metrics` (configurable via `CLICKHOUSE_METRICS_TABLE`).
- Column aliases ensure seamless compatibility across proto representations (`work_unit_id AS wid`, `step AS iteration`).

#### Query Generation by [PlotType](file:///tmp/koder_workspaces/task_532813578/xmc/api/protos/dashboard/messages.proto#L65):
- **`SUMMARY_BOX`**:
  Calculates scalar summary statistics (`latest_value`, `min_value`, `max_value`, `mean_value`, `latest_iteration`, `latest_timestamp`):
  ```sql
  SELECT
    metric_name,
    argMax(metric_value, step) AS latest_value,
    min(metric_value) AS min_value,
    max(metric_value) AS max_value,
    avg(metric_value) AS mean_value,
    max(step) AS latest_iteration,
    argMax(timestamp, step) AS latest_timestamp
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
  GROUP BY metric_name
  ```

- **`SCATTER`** (Time-series / Line plots):
  Queries continuous metrics over iterations/time. Downsampling with integer step binning is applied when downsampling resolution is requested:
  ```sql
  SELECT
    metric_name,
    work_unit_id AS wid,
    xid,
    step AS iteration,
    timestamp,
    avg(metric_value) AS avg_value,
    min(metric_value) AS min_value,
    max(metric_value) AS max_value
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
    AND step >= ? AND step <= ?
  GROUP BY metric_name, work_unit_id, xid, step, timestamp
  ORDER BY step ASC
  ```

- **`BAR` / `HISTOGRAM`**:
  Generates distribution or category frequency statistics:
  ```sql
  SELECT
    metric_name,
    toString(metric_value) AS category_or_bin,
    count() AS value_or_count
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
  GROUP BY metric_name, category_or_bin
  ```

### 3.3 Result Set Mapping (`mapper.go`)
Parses ClickHouse `driver.Rows` and converts row values into `dashboardpb.ChartData` proto payloads:
- Maps summary query rows into `ChartData_SummaryBoxValue`.
- Maps time-series rows into `ChartData_SeriesData` and `ChartData_SeriesPoint` using `timestamppb.New(time.UnixMicro(t))` for microsecond timestamp conversion.
- Maps distribution rows into `ChartData_BarData` and `ChartData_BarBucket`.

## 4. Code Standards & Architectural Guidelines Alignment
- **Single Responsibility Principle (SRP)**: Logic is partitioned into pure focused modules (`auth.go`, `translator.go`, `mapper.go`, `client.go`). Function implementations maintain a concise length (<30 lines).
- **KISS & Linear Control Flow**: Mandatory early return guard clauses on input validation and SQL execution error checks, eliminating redundant `else` blocks.
- **DRY Compliance**: Shared query parameter binding and SQL fragment building functions centralized in `translator.go`.
- **SQL Injection Prevention**: Strictly parameterized query execution using standard driver parameter replacement (`driver.Conn.Query(ctx, sql, args...)`).
