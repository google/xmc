# Technical Design & Implementation Plan: ClickHouse XMC Client Library

## 1. Executive Summary & Reviewer Question Responses

This updated technical design proposal addresses **Buganizer Task 532813578 ([XMC Flatboard] Clickhouse XMC client)**. The primary objective is to implement a robust, modular client library within [pkg/clickhouse](../../pkg/clickhouse) responsible for ClickHouse database connectivity, resilient multi-strategy authentication fallback, SQL translation from XMC proto queries, and mapping query result sets to [ChartData](../../api/protos/dashboard/messages.proto#L215-L265) proto messages.

### Detailed Answers to Reviewer Questions & Code Alignment Audit

1. **Metrics Table Schema & Column Naming Alignment**:
   - **Question**: *Is standard schema (`xid`, `wid`, `metric_name`, `metric_value`, `iteration`, `timestamp`) with configurable table name (`CLICKHOUSE_METRICS_TABLE`) acceptable?*
   - **Resolution**: **Yes, fully acceptable**. Cross-referencing [api/protos/metrics/metrics.proto](../../api/protos/metrics/metrics.proto#L23-L32) lines 23–32 confirms the core metric fields stored in XMC: `xid`, `work_unit_id`, `execution_id`, `replica_id`, `metric_name`, `metric_value`, `step`, and `timestamp` (in microseconds).
   - **Aliasing Strategy**: To bridge field naming differences between [api/protos/metrics/metrics.proto](../../api/protos/metrics/metrics.proto#L24-L31) (`work_unit_id`, `step`) and [api/protos/dashboard/messages.proto](../../api/protos/dashboard/messages.proto#L57-L58) (`wid`, `iteration`), the translation engine in [pkg/clickhouse/translator.go](../../pkg/clickhouse/translator.go) explicitly aliases ClickHouse table columns (`SELECT work_unit_id AS wid, step AS iteration...`) in generated queries.
   - **Timestamp Microsecond Conversion**: [metrics.proto](../../api/protos/metrics/metrics.proto#L31) line 31 specifies `int64 timestamp = 8; // Timestamp in microseconds`. Result set mapping in [pkg/clickhouse/mapper.go](../../pkg/clickhouse/mapper.go) converts microsecond timestamps to `google.protobuf.Timestamp` using `time.UnixMicro(t)` and `timestamppb.New`.

2. **Downsampling Algorithm & Built-in ClickHouse Functionalities**:
   - **Question**: *Should ClickHouse LTTB (Largest Triangle Three Buckets) or integer step aggregation (`floor(iteration / step)`) be prioritized for initial implementation?*
   - **Resolution**: **Leverage ClickHouse's native built-in `lttb()` aggregate function**. ClickHouse natively provides first-class support for Largest Triangle Three Buckets downsampling via the built-in `lttb(max_points)(x, y)` aggregate function (e.g., `lttb(?)(step, metric_value)` or `lttb(?)(timestamp, metric_value)`). This executes directly inside the ClickHouse engine without requiring external UDF extensions or custom plugins. The SQL translation engine in [pkg/clickhouse/translator.go](../../pkg/clickhouse/translator.go) utilizes ClickHouse's built-in `lttb()` function for time-series downsampling (`SCATTER` plots), efficiently preserving visual peaks, troughs, and data trends. For time-window bucketing, ClickHouse's native date/time interval functions (e.g., `toStartOfInterval()`) are utilized.

3. **Code Comment & Constraint Verification**:
   - Code comments in [api/protos/metrics/metrics.proto](../../api/protos/metrics/metrics.proto#L31), [api/protos/dashboard/messages.proto](../../api/protos/dashboard/messages.proto#L25-L63), [pkg/clickhouse/clickhouse.go](../../pkg/clickhouse/clickhouse.go#L30-L83), and [pkg/apis/metrics/types.go](../../pkg/apis/metrics/types.go#L25-L62) were audited. No design conflicts or rule violations were identified.

4. **`HISTOGRAM` Numeric Bucketing / Binning Strategy & ClickHouse Built-In Functions**:
   - **Question / Feedback**: *For `HISTOGRAM` plots, grouping by `toString(metric_value)` will treat every unique floating-point value as a distinct category. Consider using numeric bucketing/binning (e.g., fixed-width bins or ClickHouse numeric binning).*
   - **Resolution**: **Differentiate `BAR` and `HISTOGRAM` query generation using ClickHouse built-in functions**. For categorical `BAR` plots, grouping by `toString(metric_value)` is retained for discrete category counts. For continuous `HISTOGRAM` plots, the SQL translation engine utilizes ClickHouse native built-in functions including `histogram(num_bins)(metric_value)` and `widthBucket(metric_value, min_val, max_val, num_bins)` alongside numeric interval binning (`floor(metric_value / bin_width)`) to bucket continuous float values into bounded histogram ranges (`category_or_bin`) with frequency counts (`value_or_count`).

5. **Multi-Strategy Authentication Fallback (Option 4 - No Credentials Provided)**:
   - **Question / Feedback**: *Please add option 4 - no credentials provided - this will correspond to a setup where access is controlled at infrastructure level.*
   - **Resolution**: **Added Strategy 4 (`getOptionsNoCredentials`) to `ConnectWithFallback`**. In environments where network security, mutual TLS (mTLS), Kubernetes network policies, VPC perimeters, or sidecar authenticating proxies enforce access control at the infrastructure layer, no database-level user credentials (`Username: ""`, `Password: ""`) are required or provided. `ConnectWithFallback` evaluates this 4th fallback strategy after attempting configured credentials, configured user with empty password, and default user access.

6. **Multi-Replica Metrics Projection & Grouping (`replica_id`)**:
   - **Question / Feedback**: *`replica_id` is missing in time-series / scatter SQL query translations.*
   - **Resolution**: **Include `replica_id` in SQL projections and `GROUP BY` clauses for series query translations**. In distributed training workloads running across multiple replicas, metrics logged to ClickHouse include `replica_id` ([api/protos/metrics/metrics.proto](../../api/protos/metrics/metrics.proto#L27)) to differentiate metric streams across workers. The SQL translation engine in [pkg/clickhouse/translator.go](../../pkg/clickhouse/translator.go) projects `replica_id` in `SELECT` statements and includes `replica_id` in `GROUP BY` clauses across full-resolution, downsampled (`lttb`), and time-windowed series queries (`SCATTER`). This ensures distinct replica series are preserved and properly mapped to proto series data structures without unintended cross-worker metric conflation.

## 3. Detailed Technical Specification

### 3.1 Resilient Multi-Strategy Authentication Fallback (`auth.go`)
Per the scope requirements, `ConnectWithFallback` executes a sequential multi-strategy authentication sequence before returning an error:

1. **Strategy 1 (Primary Configured Credentials)**:
   - Reads `CLICKHOUSE_DSN` or (`CLICKHOUSE_USER` and `CLICKHOUSE_PASSWORD`).
   - Attempts connection via `clickhouse.Open(opts)` and verifies with `conn.Ping(ctx)`.
2. **Strategy 2 (Configured User with Empty Password)**:
   - Uses configured `CLICKHOUSE_USER` (or `"default"`) with empty password `""`.
   - Attempts connection and ping verification.
3. **Strategy 3 (Anonymous / Default Access)**:
   - Uses username `"default"` and password `""`.
   - Attempts connection and ping verification.
4. **Strategy 4 (No Credentials Provided / Infrastructure-Level Access Control)**:
   - Uses empty username `""` and empty password `""` (no database credentials provided), corresponding to setups where authentication and access control are managed at the infrastructure level (e.g., mTLS, Kubernetes network policies, VPC perimeters, or authenticating sidecar proxies).
   - Attempts connection and ping verification.

If all strategies fail, an aggregated error combining failure details from each step is returned.

```go
// ConnectWithFallback attempts multi-strategy authentication sequence before returning an error.
func ConnectWithFallback(ctx context.Context) (driver.Conn, error) {
    var errs []error
    strategies := []func() (*clickhouse.Options, error){
        GetOptions,
        getOptionsUserNoPassword,
        getOptionsDefaultUser,
        getOptionsNoCredentials,
    }
    for _, getOpts := range strategies {
        opts, err := getOpts()
        if err != nil {
            errs = append(errs, err)
            continue
        }
        conn, err := clickhouse.Open(opts)
        if err != nil {
            errs = append(errs, err)
            continue
        }
        if err := conn.Ping(ctx); err == nil {
            return conn, nil
        }
        conn.Close()
    }
    return nil, fmt.Errorf("all clickhouse auth strategies failed: %v", errs)
}
```

### 3.2 SQL Query Translation Engine (`translator.go`)
Translates XMC proto definitions from [api/protos/dashboard/messages.proto](../../api/protos/dashboard/messages.proto) into parameterized ClickHouse SQL statements.

#### Schema & Aliasing Assumptions:
- Table name defaults to `xmc_metrics` (configurable via `CLICKHOUSE_METRICS_TABLE`).
- Column aliases and multi-replica identifiers ensure seamless compatibility across proto representations (`work_unit_id AS wid`, `step AS iteration`, `replica_id`).

#### Query Generation by [PlotType](../../api/protos/dashboard/messages.proto#L65):
- **`SUMMARY_BOX`**:
  Calculates scalar summary statistics (`latest_value`, `min_value`, `max_value`, `mean_value`, `latest_iteration`, `latest_timestamp`) using ClickHouse native built-in aggregate and combinator functions (`argMax`, `min`, `max`, `avg`):
  ```sql
  SELECT
    metric_name,
    argMax(metric_value, step) AS latest_value,
    min(metric_value) AS min_value,
    max(metric_value) AS max_value,
    avg(metric_value) AS mean_value,
    max(step) AS latest_iteration,
    argMax(timestamp, step) AS latest_timestamp
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
  GROUP BY metric_name
  ```

- **`SCATTER`** (Time-series / Line plots):
  Queries continuous metrics over iterations/time. When downsampling is requested, ClickHouse's native built-in `lttb(max_points)(step, metric_value)` aggregate function is utilized:
  ```sql
  SELECT
    metric_name,
    work_unit_id AS wid,
    xid,
    replica_id,
    lttb(?)(step, metric_value) AS downsampled_points
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
    AND step >= ? AND step <= ?
  GROUP BY metric_name, work_unit_id, xid, replica_id
  ```
  For time-windowed series aggregation, ClickHouse native built-in date/time interval functions (e.g., `toStartOfInterval(fromUnixTimestamp64Micro(timestamp), INTERVAL ? SECOND)`) are utilized:
  ```sql
  SELECT
    metric_name,
    work_unit_id AS wid,
    xid,
    replica_id,
    toStartOfInterval(fromUnixTimestamp64Micro(timestamp), INTERVAL ? SECOND) AS interval_window,
    avg(metric_value) AS avg_value,
    min(metric_value) AS min_value,
    max(metric_value) AS max_value
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
    AND timestamp >= ? AND timestamp <= ?
  GROUP BY metric_name, work_unit_id, xid, replica_id, interval_window
  ORDER BY interval_window ASC
  ```
  For standard full-resolution series queries:
  ```sql
  SELECT
    metric_name,
    work_unit_id AS wid,
    xid,
    replica_id,
    step AS iteration,
    timestamp,
    avg(metric_value) AS avg_value,
    min(metric_value) AS min_value,
    max(metric_value) AS max_value
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
    AND step >= ? AND step <= ?
  GROUP BY metric_name, work_unit_id, xid, replica_id, step, timestamp
  ORDER BY step ASC
  ```

- **`BAR`** (Categorical / Discrete frequency plots):
  Generates discrete category frequency statistics using ClickHouse native built-in functions (`count()`, `toString()`):
  ```sql
  SELECT
    metric_name,
    toString(metric_value) AS category_or_bin,
    count() AS value_or_count
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
  GROUP BY metric_name, category_or_bin
  ```

- **`HISTOGRAM`** (Continuous distribution / Numeric binning plots):
  Leverages ClickHouse's native built-in histogram aggregate function `histogram(num_bins)(metric_value)` and built-in bucketing function `widthBucket(metric_value, min_val, max_val, num_bins)` alongside numeric interval binning (`floor(metric_value / bin_width)`) to group continuous floating-point metrics into bounded numeric buckets:
  ```sql
  SELECT
    metric_name,
    histogram(?)(metric_value) AS histogram_buckets
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
  GROUP BY metric_name
  ```
  Or for equi-width interval binning queries:
  ```sql
  SELECT
    metric_name,
    concat(toString(floor(metric_value / ?) * ?), ' - ', toString((floor(metric_value / ?) + 1) * ?)) AS category_or_bin,
    count() AS value_or_count
  FROM xmc_metrics
  WHERE xid = ? AND work_unit_id = ? AND metric_name IN (?)
  GROUP BY metric_name, category_or_bin
  ORDER BY floor(metric_value / ?) ASC
  ```

### 3.3 Result Set Mapping (`mapper.go`)
Parses ClickHouse `driver.Rows` and converts row values into `dashboardpb.ChartData` proto payloads:
- Maps summary query rows into `ChartData_SummaryBoxValue`.
- Maps time-series rows into `ChartData_SeriesData` and `ChartData_SeriesPoint` using `timestamppb.New(time.UnixMicro(t))` for microsecond timestamp conversion and preserving `replica_id` across multi-replica metric streams.
- Maps distribution rows into `ChartData_BarData` and `ChartData_BarBucket`.

## 4. Code Standards & Architectural Guidelines Alignment
- **Single Responsibility Principle (SRP)**: Logic is partitioned into pure focused modules (`auth.go`, `translator.go`, `mapper.go`, `client.go`). Function implementations maintain a concise length (<30 lines).
- **KISS & Linear Control Flow**: Mandatory early return guard clauses on input validation and SQL execution error checks, eliminating redundant `else` blocks.
- **DRY Compliance**: Shared query parameter binding and SQL fragment building functions centralized in `translator.go`.
- **SQL Injection Prevention**: Strictly parameterized query execution using standard driver parameter replacement (`driver.Conn.Query(ctx, sql, args...)`).
