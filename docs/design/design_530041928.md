   - Check if any `ResourceFlavor` in the cluster advertises TPU topologies (i.e. possesses the `cloud.google.com/gke-tpu-topology` label).
   - If **none** do, it will log an info message and proceed (relying on downstream Kubernetes scheduling failure if the topology is actually invalid).
   - If **at least one** does, it will strictly enforce that the requested topology matches one of the advertised topologies.
